# v1.0.0 博客模块首版

- 日期：2026-09-18
- 需求来源：在若依中新建博客后端模块；文章增加字数统计、阅读时长
- 功能版本：1.0.0

## 要解决什么

给个人/技术博客提供后台写作与前台阅读接口。管理端走若依登录和权限，游客只读已发布文章。文章要能展示字数和预计阅读分钟数。

## 设计考虑

### 为什么独立模块而不是塞进 ruoyi-system

系统管理（用户、角色、菜单）和内容域生命周期不同。对齐 `ruoyi-quartz`：只依赖 `ruoyi-common`，由 `ruoyi-admin` 引入。MyBatis 已扫描 `com.ruoyi.**.mapper` 和 `classpath*:mapper/**/*Mapper.xml`，新模块不用改全局配置。

### 后台 / 前台拆 Controller

- `/cms/**`：登录 + `@PreAuthorize`，可看草稿、可改状态
- `/portal/cms/**`：`@Anonymous`，只查 `status=已发布` 且未删除

同一套 Service，避免两套 Mapper。列表 SQL 不查 `content`，详情才带正文，避免分页被大字段拖死。

公开接口用 `@Anonymous`，不改 `SecurityConfig` 白名单，后续加路径不容易漏配。

### 正文用 Markdown 且字数落库

正文存 Markdown，比直接存 HTML 更好做 XSS 收敛。字数、阅读时长**不让前端传**：保存/更新时服务端根据正文重算，列表页才能不解析 content。

统计规则（中文博客）：

1. 去掉围栏代码块、HTML 标签、图片/链接的 URL，链接保留可见文字
2. CJK 每个字计 1，剩余拉丁片段按空白分词计 1
3. `reading_time = max(1, ceil(中文字数/400 + 英文词数/200))`；空正文为 0 字、0 分钟

400/200 是经验值，不是精确人读速度。若以后要可配置，再抽到参数表，不在首版做。

### 状态与删除

- `0` 草稿 `1` 已发布 `2` 下线
- 首次变为已发布时写 `publish_time`，之后改稿不刷新，保证列表按首次发布时间排序
- `del_flag`：`0` 存在 `2` 删除（跟若依惯例），不用物理删文章；标签关系在删文章时清掉，避免脏中间表

### slug

分类、标签、文章都有 slug，给前台友好 URL。空 slug 存 `NULL`（MySQL 唯一索引允许多个 NULL）。冲突在 Service 校验，不依赖报错码。

### 作者不绑 sys_user

`author` 用字符串，默认当前登录名。博客模块不反向依赖 `ruoyi-system`，避免循环依赖。

### 分类先扁平

表留 `parent_id`，接口按扁平用。个人博客层级很少，树形等到真有需求再做，避免首版菜单和查询复杂化。

### 明确不做（首版）

评论、点赞、专题/专栏、富文本、浏览量防刷（Redis）、全文检索。浏览量详情接口直接 `view_count + 1`。

## 数据变更

新库执行 `sql/cms_v1.0.0.sql`：

- `cms_category`、`cms_tag`、`cms_article`、`cms_article_tag`
- `cms_article.word_count`、`cms_article.reading_time`
- 菜单：博客管理 / 文章 / 分类 / 标签及按钮权限
- 字典：`cms_article_status`

无历史数据。超级管理员看全部菜单，无需插 `sys_role_menu`。

## 接口变更

后台：`/cms/article`、`/cms/category`、`/cms/tag` 标准 CRUD；文章另有 `PUT /cms/article/publish/{id}`、`PUT /cms/article/offline/{id}`。

前台：列表、id/slug 详情、分类、标签、热门。详情会增加浏览量。

## 实现要点

- 权限字：`cms:article:*`、`cms:category:*`、`cms:tag:*`（含 publish / offline）
- 封面复用若依 `/common/upload`
- 文章保存事务内重写 `cms_article_tag`
